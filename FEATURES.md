# Тихонов Клочкова онлайн мморпг 3 в ряд - Функциональные возможности

## Общее описание

"Тихонов Клочкова онлайн мморпг 3 в ряд" - это многопользовательская онлайн-игра, сочетающая элементы головоломки "три в ряд" с MMORPG механиками. Игроки могут соревноваться друг с другом или с ботами в увлекательной головоломке, получая за победы ценные награды в виде предметов различного качества.

## Основные функции

### 1. Игровой режим "три в ряд"
- **Игровое поле**: 8x8 клеток с 6 различными типами камней
- **Механика**: Обмен соседними камнями для создания линий из 3 и более одинаковых
- **Каскады**: Автоматическое заполнение пустых клеток новыми камнями после уничтожения линий
- **Счет**: Очки начисляются за каждую уничтоженную линию (10 очков за каждый камень в линии)

### 2. Боевая система
- **Здоровье**: У каждого игрока изначально 100 HP + бонусы от экипированных предметов
- **Таймер**: Каждый матч ограничен 45 секундами
- **Победа**: 
  - В обычной игре: игрок с наибольшим количеством очков
  - По истечении времени: игрок с наибольшим количеством HP
  - При равных показателях: победитель определяется случайным образом

### 3. Система противников
- **Боты**: Случайные результаты, как указано в требованиях
- **Другие игроки**: Реальные соперники в рейтинговых матчах
- **Рейтинг**: Система Эло для определения силы игроков

### 4. Система наград
- **Предметы**: Выдаются за победы в матчах
- **Качество**: 6 уровней - от обычного (common) до мифического (mythic)
- **Типы**: Оружие (weapon), доспехи (armor), аксессуары (accessory)
- **Бонусы**: Увеличение HP, атаки и защиты

### 5. Персонаж и экипировка
- **Профиль**: Имя, уровень, опыт, здоровье
- **Инвентарь**: Хранение и управление предметами
- **Экипировка**: Применение предметов для увеличения характеристик

### 6. Рейтинговая система
- **Рейтинг Эло**: Для определения силы игрока
- **Статистика**: Победы/поражения
- **Таблица лидеров**: Публичный рейтинг игроков

### 7. Админ-панель
- **Управление игроками**: Просмотр, редактирование, удаление
- **Управление предметами**: Выдача и изъятие предметов у игроков
- **Просмотр матчей**: История всех игр
- **Мониторинг**: Статистика и активность

## Архитектурные особенности

### 1. Распределенная обработка
- **Kafka**: Брокер сообщений для асинхронной обработки матчей
- **Отделенный процессор**: Отдельный сервис для обработки результатов матчей
- **Frontend/Backend разделение**: Четкое разделение клиентской и серверной логики

### 2. Безопасность
- **Серверная валидация**: Все результаты матчей проверяются на сервере
- **Защита от читов**: Клиент может отправлять только счет, сервер определяет результат

### 3. Масштабируемость
- **Микросервисная архитектура**: Отдельные сервисы для разных функций
- **Сообщения через Kafka**: Возможность масштабирования обработки матчей
- **REST API**: Для взаимодействия между сервисами

## Технические требования

### 1. Временные ограничения
- **45 секунд на матч**: Жесткое ограничение продолжительности игры
- **Таймер на UI**: Отображение оставшегося времени
- **Авто-победитель**: При истечении времени побеждает игрок с большим HP

### 2. Система очков
- **Фронтенд**: Подсчет очков на клиенте
- **Сервер**: Валидация и определение результата на сервере
- **Python**: Обработка результатов на бэкенде

### 3. Использование Kafka
- **Сообщения о матчах**: Через топик 'match_requests'
- **Результаты**: Через топик 'match_results'
- **Асинхронная обработка**: Для масштабируемости и отказоустойчивости

## Игровой процесс

1. Игрок заходит в игру и выбирает режим (против бота или другого игрока)
2. Начинается матч с таймером в 45 секунд
3. Игрок играет в "три в ряд", набирая очки
4. По окончании времени или досрочно определяется победитель
5. Победитель получает случайный предмет в награду
6. Результат сохраняется в системе, рейтинг обновляется

## Административные функции

1. Просмотр всех игроков и их статистики
2. Просмотр истории матчей
3. Выдача/изъятие предметов у игроков
4. Управление аккаунтами игроков
